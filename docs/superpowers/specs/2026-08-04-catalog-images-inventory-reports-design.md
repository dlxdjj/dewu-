# 商品图片、库存分组与经营指标设计

日期：2026-08-04  
状态：已确认，采用方案 1

## 1. 目标

本次改造在不破坏现有进销存数据、结算流程和 GitHub Pages 静态部署的前提下，完成以下事项：

- 新增采购时必须填写货号，并可上传商品图片。
- 同一货号已经上传过图片时，在新增页面自动提示并展示；不选新图就复用，选择新图后以新图为准。
- 库存先按购入平台筛选，再将相同货号、相同尺码的记录合并显示。
- 首页保留库存数量、库存成本，并显示当月销量、当月利润。
- 报表提供历史总利润、总销售额、总销量，以及指定月份的同一组三项指标。
- 修复 iPhone 上采购日期输入框超出屏幕的问题。

不在本次范围内：得物挂牌价、OCR 逻辑调整、离线写入队列、新建商品图片表、删除或强制清理历史无货号数据。

## 2. 方案选择

采用方案 1：复用现有 `attachments` 元数据、Supabase 私有 `attachments` Storage bucket 和签名 URL；库存分组在客户端完成；只增加一份小型安全迁移来强化货号必填规则。

选择理由：项目已经具备商品附件、图片压缩、私有存储、签名访问和库存分组组件，复用这些能力可减少数据库变更和部署风险，同时满足当前业务需求。

## 3. 数据与业务口径

### 3.1 货号

- 新增采购时货号为硬性必填项，前端表单、服务层和数据库 RPC 都必须拒绝空白货号。
- 判空前先去除首尾空格；只有空格也视为未填写。
- 货号匹配采用去除首尾空格后的不区分大小写比较。
- 现有历史无货号数据继续保留并可查看，不因迁移失败或被自动删除；规则只约束后续新增数据。
- 数据库迁移应采用兼容历史数据的约束方式，并在采购 RPC 内显式校验，避免旧数据阻塞部署。

### 3.2 商品图片

- 图片继续保存为 `owner_type = product`、`kind = product_image` 的附件，不新增图片表。
- 文件保存在私有 Storage bucket，通过短期签名 URL 显示，不能将私有原图 URL 直接公开。
- 使用现有图片选择与压缩逻辑：最长边 1200 像素，JPEG 质量 0.82。
- 用户输入有效货号后，系统查找对应商品，并读取该商品最新一张 `product_image`。
- 找到历史图片时，新增页面显示缩略图和“该货号已有图片，将默认复用”的状态。
- 用户不选择新图片：采购创建成功后不重复上传，库存继续显示已有图片。
- 用户选择新图片：先创建采购，再用返回的 `productId` 上传新附件；之后以最新附件作为该货号的展示图片。
- 若采购保存成功而图片上传失败，不回滚已经保存的采购记录。页面必须明确提示“商品已保存，图片上传失败”，允许用户以后用同一货号重新选择图片补传。
- 图片签名 URL 加载失败时显示占位图，不影响库存、筛选和业务操作。

### 3.3 库存合并规则

库存页的处理顺序固定为：

1. 读取库存明细。
2. 应用购入平台筛选。
3. 对筛选结果按“标准化货号 + 标准化尺码”合并。

标准化规则：去除首尾空格并采用不区分大小写的货号；尺码去除首尾空格后用于分组。相同货号、相同尺码即为同组，成本、状态、采购批次不同也必须合并。

平台筛选第一版只包含“全部”和现有数据中出现的购入平台，例如淘宝、拼多多。选择某个平台时只显示该平台购入的记录；选择“全部”时允许一个分组包含多个平台，并显示“多平台”或平台标签。

合并卡片展示：

- 最新商品图片或占位图。
- 商品名称、货号、尺码。
- 该组记录数量。
- 该组采购成本合计。
- 状态数量分布。
- 购入平台标签。

点击分组进入明细页，列出组内每一件商品的采购平台、单件成本、状态和现有可执行操作。分组详情的定位条件改为货号、尺码以及可选平台，不再把成本和状态作为分组条件。

批量模式下选中一个分组，等于选中组内全部底层库存单元；现有批量发货、结算和状态变更仍对这些底层单元执行。

### 3.4 首页指标

首页只保留四个核心指标：

- 库存数量：当前有效库存单元数量。
- 库存成本：当前有效库存单元的采购成本合计。
- `N月销量`：当前自然月已结算销售记录数量。
- `N月利润`：当前自然月已结算销售记录的利润合计。

当前有效库存状态沿用现有定义：`pending`、`arrived`、`shipping`、`in_stock_dewu`、`returned`。库存成本为这些单元 `unit_cost_cents` 的合计。

当月销量和利润以 `settled_at` 落在当前自然月为准。利润口径保持为：实际到账金额减采购成本、减发出运费。

删除首页“未结算”卡片和“利润唯一口径”提示框，不在首页显示销售额或其他报表指标。

### 3.5 报表指标

报表顶部展示历史累计：

- 总利润。
- 总销售额。
- 总销量。

报表提供月份选择器。选择月份后展示该月：

- 利润。
- 销售额。
- 销量。

统计口径：

- 时间统一按实际结算记录的 `settled_at` 归属月份。
- 销售额为 `actual_payout_cents` 合计。
- 销量为有效、非退款结算记录数量。
- 利润为 `actual_payout_cents - unit_cost_cents - outbound_shipping_cents` 的合计。
- 历史累计使用全部有效、非退款的实际结算记录。

报表不再展示与销售报表无关的“有效库存成本”。CSV 导出同步增加历史累计和所选月份的利润、销售额、销量，采用与页面一致的口径。

## 4. 页面与交互改动

### 4.1 新增页面

- 货号标签显示必填标记，空白时阻止提交并给出中文提示。
- 货号输入稳定后查询已有商品图片，查询期间显示轻量加载状态。
- 展示已有图片缩略图、复用说明和选择/替换图片入口。
- 提交按钮在采购保存与图片上传期间避免重复提交。
- 采购日期输入框使用受容器约束的宽度样式，包括 `width: 100%`、`min-width: 0`、`max-width: 100%` 和 `box-sizing: border-box`，确保 iPhone Safari 不产生横向溢出。

### 4.2 库存页面

- 页面顶部增加横向可滚动或自动换行的平台筛选按钮，默认选择“全部”。
- 列表由单件卡片改为按货号和尺码合并的分组卡片。
- 筛选无结果时显示明确空状态。
- 保留搜索、刷新、批量操作和单件明细能力，但其数据源改为筛选后的分组及底层单元。

### 4.3 首页与报表

- 首页四张卡片在移动端保持现有紧凑布局，月份标签随当前月份自动更新。
- 报表历史累计与月度统计分区展示，月份切换只改变月度区域，不改变历史累计。
- 金额统一沿用项目现有货币格式化方式。

## 5. 数据访问与性能

- 商品、库存和附件元数据尽量批量读取，避免对每一条库存记录单独查询附件元数据。
- 每个可见货号只解析最新一张商品图片；签名 URL 可按唯一附件生成并在页面生命周期内复用。
- 数据库采购 RPC 返回的 `productId` 继续作为新图片附件的所有者 ID。
- 不改变 GitHub Pages 静态导出模式；所有浏览器端 Supabase 调用继续使用构建期注入的公开 URL 与 anon/publishable key。
- 不把数据库密码、service role key 或其他服务端秘密写入前端、Git 仓库或静态产物。

## 6. 数据库迁移

新增顺序迁移 `0003`，职责仅限货号规则的数据库防线：

- 更新或替换 `create_purchase_simple`，在写入前拒绝 `null`、空字符串和仅空格货号。
- 为后续直接写入提供兼容历史数据的非空白检查约束；已有不合规历史行不阻塞迁移。
- 保留当前不区分大小写的货号去重行为和 RPC 权限模型。
- 不删除、覆盖或批量修改现有业务数据。

## 7. 错误处理与一致性

- 货号查询失败：允许用户保留输入，但提交时仍执行完整校验；显示可重试错误。
- 图片读取失败：显示占位图，不阻塞业务数据加载。
- 图片上传部分失败：保留已创建采购并明确告知结果，避免向用户谎报全部失败或全部成功。
- 分组中的任一底层单元操作失败时，沿用现有批量结果反馈，成功项和失败项分别报告。
- 月份没有结算数据时，利润、销售额、销量显示为零，而不是空白或错误。

## 8. 测试与验收

实现采用测试驱动方式，至少覆盖：

- 货号在 UI、服务层和 RPC 均为必填，空格货号被拒绝，历史无货号记录仍可读取。
- 输入已有货号时显示最新图片；不选图复用；选新图后最新图生效；图片上传失败时采购仍保存并给出准确提示。
- 平台筛选先于分组执行。
- 相同货号与尺码在成本、状态、批次不同的情况下仍合并为一组；不同尺码不合并。
- “全部”平台分组与单平台筛选结果正确，平台标签正确。
- 分组选择能映射到全部底层单元，现有批量操作行为不回归。
- 首页库存数量、库存成本和当前月销量、利润计算正确，跨月记录不混入。
- 报表历史累计和所选月份的利润、实际到账销售额、销量计算正确；退款记录按既定规则排除。
- CSV 与页面指标一致。
- iPhone 宽度下采购日期控件处于卡片边界内，页面 `scrollWidth` 不超过 `innerWidth`。
- 完整单元测试、类型检查、代码规范检查、生产构建和静态导出通过。
- 部署后在公开 GitHub Pages 地址验证登录、首页、添加、库存筛选/分组、图片显示和报表。

## 9. 完成标准

以下条件全部满足才算完成：

- 新增采购无法提交空白货号。
- 商品图片可新增、复用、替换，并在库存分组中稳定显示。
- 库存平台筛选和“货号 + 尺码”合并符合约定，明细及批量操作仍可用。
- 首页只显示约定的四项指标，数值和月份正确。
- 报表历史与月度三项指标、CSV 口径一致。
- iPhone 日期输入不再溢出。
- 数据迁移安全、测试和构建通过，GitHub Pages 静态部署正常。
